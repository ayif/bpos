# Task — 05 Agustus 2026

## Ringkasan Aplikasi

**BPOS** — Sistem Point of Sale & Manajemen Multi Cabang.

- **Backend**: Node.js/TypeScript (Express + Prisma ORM), PostgreSQL, Redis (cache/session).
- **Frontend**: Next.js (App Router).
- **Deploy**: Docker Compose (postgres, redis, backend, frontend).
- **Modul backend** (`backend/src/modules/`): auth, users, branches, products, stock, purchasing, customers, pos, shift, expense, accounting, reports, settings, ppob.
- **Halaman frontend** (`frontend/src/app/(app)/`): dashboard, pos, products, stock, purchasing, customers, expenses, accounting, reports, shift, branches, users, ppob, settings.
- **Fitur inti yang sudah lengkap**: login JWT + role & permission per cabang, POS (checkout multi-metode bayar, split payment, diskon, pajak, cetak struk, retur), stok FIFO per cabang (batch costing), transfer stok antar cabang, stock opname + audit trail, PO → penerimaan barang (otomatis update stok & jurnal), pelanggan & loyalty (poin, price level otomatis), akuntansi double-entry (jurnal otomatis + Neraca/Laba Rugi/Arus Kas), laporan penjualan/laba FIFO COGS, shift kasir, cetak label barcode, pengaturan per cabang.
- **Modul yang masih level dasar** (sesuai README):
  - PPOB (`backend/src/modules/ppob/`) — masih **mode mock** (`DIGIFLAZZ_MODE=mock`), integrasi live ke Digiflazz belum diverifikasi dengan kredensial nyata.
  - Sebagian laporan turunan akuntansi (`backend/src/modules/accounting/`, `reports/`) belum lengkap.
  - Detail UI lanjutan, misalnya approval multi-level untuk Purchase Order (`backend/src/modules/purchasing/`), belum dikembangkan.
- **Catatan verifikasi dari README**: `npx prisma generate` belum pernah dijalankan di sandbox pembuatan project (diblokir akses ke `binaries.prisma.sh`) — perlu dijalankan di lingkungan dengan akses internet penuh sebelum backend benar-benar bisa jalan.

### 2. PPOB — Integrasi Digiflazz Live — ✅ Selesai sebagian (06 Agustus 2026)
Dikerjakan tanpa kredensial live sungguhan (belum tersedia) — semua yang bisa diverifikasi tanpa akun Digiflazz asli sudah selesai & diuji end-to-end. Uji coba mode live sungguhan jadi item terbuka.
- [x] Review `backend/src/modules/ppob/digiflazz.client.ts` terhadap skema Digiflazz: signature MD5 `username+apiKey+refId` untuk `/transaction` dan `username+apiKey+"pricelist"` untuk `/price-list` sudah benar. **Bug diperbaiki**: mapping status sebelumnya (`status==="Sukses" ? SUCCESS : rc==="00" ? PENDING : FAILED`) menyimpulkan PENDING dari `rc` alih-alih mengecek nilai `status` ("Pending"/"Gagal") secara eksplisit seperti didokumentasikan Digiflazz — sekarang `mapDigiflazzStatus()` mengecek ketiga nilai status secara eksplisit, `rc` cuma fallback kalau field status hilang/tak dikenal.
- [x] Tambah `DIGIFLAZZ_TESTING=true` (baru, di `.env.example`) — kirim `testing: true` ke Digiflazz saat live mode, supaya begitu ada kredensial sandbox, transaksi uji tidak memotong saldo asli. **Belum bisa diverifikasi live** karena tidak ada kredensial — kalau nanti tersedia, tinggal set `DIGIFLAZZ_MODE=live` + `DIGIFLAZZ_USERNAME`/`DIGIFLAZZ_API_KEY` + `DIGIFLAZZ_TESTING=true` di `.env` lalu rebuild backend.
- [x] Timeout & error handling: `callDigiflazz()` helper baru pakai `AbortController` (timeout 15s), menangani response non-JSON dan HTTP non-2xx dengan `DigiflazzError` alih-alih hang/crash. Di route `POST /ppob/transactions`, `DigiflazzError` di-map ke `502 Bad Gateway` **tanpa membuat row transaksi** (supaya tidak ada transaksi macet kalau provider tidak bisa dihubungi).
- [x] Endpoint callback/webhook baru: `POST /api/ppob/callback?token=...` (`backend/src/modules/ppob/ppob.routes.ts`) — didaftarkan **sebelum** middleware `authenticate` (Digiflazz tidak bisa kirim JWT kita), diproteksi shared-secret `DIGIFLAZZ_CALLBACK_TOKEN` (wajib diisi, endpoint menolak semua request kalau env var ini kosong). Idempoten: callback ganda pada transaksi yang sudah terminal (SUCCESS/FAILED) diabaikan.
- [x] Mode mock dibuat realistis (sebelumnya selalu SUCCESS instan): sekarang distribusi acak berbobot ~70% SUCCESS / ~20% PENDING / ~10% FAILED langsung, dan transaksi PENDING di mock mode di-auto-resolve 4-8 detik kemudian (~75% sukses/25% gagal) lewat helper `applyDigiflazzResult()` yang sama persis dipakai callback asli — jadi seluruh alur pending→terminal teruji tanpa kredensial nyata. Catatan: auto-resolve mock ini in-memory (`setTimeout`), jadi kalau backend restart sebelum timer jalan, transaksi mock tetap PENDING selamanya — beda dengan callback asli Digiflazz yang tidak terpengaruh restart kita.
- [x] Field `updatedAt` ditambahkan ke model `PpobTransaction` (sebelumnya cuma ada `createdAt`) supaya jelas kapan status terakhir berubah.
- [x] UI `frontend/src/app/(app)/ppob/page.tsx`: badge status berwarna (kuning/hijau/merah), kolom SN & keterangan pesan, dan polling otomatis tiap 3 detik selama masih ada transaksi PENDING (pakai `refreshInterval` dinamis dari SWR) — status berubah di layar tanpa refresh manual.
- [x] Diuji end-to-end via API: 12 transaksi mock (distribusi tervariasi), auto-resolve PENDING→SUCCESS setelah ~9 detik, callback dengan token salah (401), ref tidak dikenal (404), callback resolve sukses + SN tersimpan, dan callback duplikat pada transaksi yang sudah terminal (diabaikan, status tidak berubah).
- [ ] **Uji coba mode live dengan kredensial sandbox Digiflazz sungguhan** — belum bisa dilakukan, menunggu Anda mendaftar akun developer Digiflazz dan mengisi `DIGIFLAZZ_USERNAME`/`DIGIFLAZZ_API_KEY` di `.env`. Setelah itu: set `DIGIFLAZZ_MODE=live`, `DIGIFLAZZ_TESTING=true`, isi `DIGIFLAZZ_CALLBACK_TOKEN`, daftarkan URL callback (`https://<host-publik-anda>/api/ppob/callback?token=<token>`) di dashboard Digiflazz (perlu URL publik — `localhost` tidak bisa diakses Digiflazz, perlu tunnel seperti ngrok untuk uji lokal), lalu `docker compose up -d --build backend`.
